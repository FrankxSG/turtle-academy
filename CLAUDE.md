# Turtle Academy — Claude entrypoint

Read `docs/AI_COLLABORATION.md`, `docs/TECHNICAL_DESIGN_DECISIONS.md`, `docs/FEATURE_SCOPE.md`, `docs/PILOT_V0_1_SCOPE.md`, `docs/TECHNICAL_HANDOFF.md` and `docs/FOUNDATION_SETUP.md` before work.

**Prepare every contribution for public publication, even while the repository is private.** Published commits, branches, PR descriptions, Issues, comments and CI logs can be copied and cannot be reliably withdrawn. Never include learner names, school details, worksheets, handwriting, photos, progress records, account identifiers, infrastructure project details or credentials, even temporarily.

GitHub is the shared source of truth for Claude and ChatGPT. Check the current main SHA and relevant open PRs; unmerged code is not the main baseline. Use the common collaboration protocol instead of a separate Claude rule set. Record task progress, decisions and test evidence in the repository/Issues/PRs, not only in chat. Follow `docs/AI_COLLABORATION.md`: branch prefixes `claude/` and `chatgpt/`, the seven-step task lifecycle, proportional checks, and per-PR merge authorization from the owner (in chat or on GitHub, recorded on the PR before merging). No standing merge or deployment permission exists.

No runtime AI, real learner fixtures, privileged frontend keys or cross-project resource reuse. Preserve private learner storage, offline records and the distinction between submission/story/mastery. Full feature scope is not the Pilot build list: `docs/PILOT_V0_1_SCOPE.md` defines the only committed delivery slice. Merging and deployment remain separately approved actions. Later explicit owner instructions supersede stale records and must be reconciled in GitHub.
